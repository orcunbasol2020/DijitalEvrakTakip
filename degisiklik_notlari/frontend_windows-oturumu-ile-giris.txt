Windows oturumu ile otomatik giriş: ön yüz notu

Backend dalı: feature/atlas-transfer-queue
Canlıda kullanıcı giriş ekranı görmeden, bilgisayarda açık olan Windows (AD) hesabıyla otomatik giriş yapacak.
Geliştirme ortamında giriş formu kalıyor (her kullanıcıyla test için); ama artık ŞİFRESİZ, yalnızca kullanıcı adı
istenir (bkz. frontend_com-kullanici-ve-birim.txt, "4) Giriş").


1) Yeni uç noktalar

- GET api/Users/GetLoginOptions  (token gerekmez)
      { "formLoginEnabled": false, "windowsLoginEnabled": true }
  Canlıda formLoginEnabled false, local'de true gelir.

- POST api/Users/WindowsLogin  (gövde yok)
  - MUTLAKA withCredentials: true ile çağrılmalı; yoksa tarayıcı Windows kimliğini göndermez.
  - Cevap: POST api/Users/Login ile birebir aynı UserLoginDto (token, tokenExpiration, roles, birim ...).
    Token bundan sonra eskisi gibi Authorization: Bearer ile kullanılır; diğer çağrılarda withCredentials gerekmez.
  - 401: Windows kimliği doğrulanamadı (bilgisayar domain'de değil, tarayıcı ayarı / GPO eksik vb.).
  - 403: Kullanıcı sistemde tanımlı değil, silinmiş ya da pasif.

- POST api/Users/Login: formLoginEnabled false iken 404 döner.


2) Önerilen akış (uygulama açılışı)

1. Geçerli (süresi dolmamış) token varsa doğrudan devam.
2. Yoksa GetLoginOptions çağrılır.
3. windowsLoginEnabled true ise WindowsLogin çağrılır (withCredentials: true):
   - 200 -> token saklanır, kullanıcı içeri alınır; giriş ekranı hiç görünmez.
   - 403 -> "Sistemde tanımlı değilsiniz ya da hesabınız pasif. Sistem yöneticisine başvurun." ekranı.
   - 401 / ağ hatası -> formLoginEnabled true ise giriş formu, değilse "Windows oturumunuz doğrulanamadı" ekranı.
4. windowsLoginEnabled false ve formLoginEnabled true ise bugünkü giriş formu.

Local'de iki giriş de açık. Geliştirme sırasında başka kullanıcıyla test etmek için:
- Ya giriş formu her zaman gösterilsin ve yanında "Windows hesabımla gir" düğmesi olsun,
- Ya da formLoginEnabled true iken otomatik Windows girişi yapılmasın, form açılsın (önerilen; dev'de
  Windows girişi düğmeyle denenebilir).

Token süresi dolunca (401) canlıda kullanıcıyı giriş ekranına değil, WindowsLogin'e yeniden yönlendirmek yeterli;
sessizce yeni token alınır. Çıkış (logout) canlıda anlamsız kalır: tekrar açılışta otomatik girilir. Çıkış düğmesi
canlıda gizlenebilir ya da "oturumu yenile" gibi davranabilir.


3) Interceptor

- endpointInterceptor istekleri dets-backend-route-lan-dets.apps.ocp.mfa.gov.tr'ye yönlendiriyor (farklı adres).
  Backend bu yüzden yalnızca kendi ön yüz adresimize kimlik bilgili CORS izni veriyor (Cors:AllowedOrigins).
  Ön yüzün canlı adresi backend ekibine bildirilmeli; adres değişirse backend ayarı da değişmeli.
- Token ekleyen interceptor WindowsLogin isteğine Authorization: Bearer EKLEMEMELİ (Negotiate başlığıyla çakışır;
  tarayıcı Authorization başlığı varsa Windows kimliğini göndermez).
